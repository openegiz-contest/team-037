# Цифровой двойник карьера Актогай

Веб-прототип для хакатона «Цифровой рудник»: цифровой двойник открытого медного карьера
с интеллектуальной диспетчеризацией самосвалов. Два карьера с одинаковыми случайными событиями
работают рядом: слева самосвалы закреплены за экскаваторами, справа их распределяет «умный» диспетчер.

> Модель построена по открытым данным. Операционные данные смоделированы. Проект не связан с KAZ Minerals.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тесты движка (Vitest)
npm run bench      # бенчмарк стратегий → BENCHMARK.md
npm run build      # продакшен-сборка в dist/
```

`npm run bench -- 25 1 20` запускает 25 самосвалов на seed 1–20.

### Управление на демо

| Действие | Кнопка | Клавиша |
|---|---|---|
| Работа без остановки | смена стартует сама, по окончании сразу начинается следующая; паузы нет | — |
| Скорость | x1 / x5 / x20 / x50 / ⏩ МАКС (x1 = 10 с смены за 1 с) | — |
| Поломка экскаватора на 50 мин (выбранного или следующего по кругу) | ⚠ Вызвать поломку | B |
| Взрывные работы у выбранного (или следующего) экскаватора через 15 мин | 💥 Взрыв | E |
| Перекрыть участок съезда на 40 мин | ⛔ Перекрыть съезд | C |
| Сброс | ↺ Сброс | R |

**3D-вид (по умолчанию) и 2D-схема** переключаются в шапке. В 3D: ЛКМ — вращение, ПКМ — сдвиг,
колесо — масштаб; кнопки «Общий вид / Дробилка / Дно карьера / Смотровая» (вид с восточной смотровой площадки), «⟳ Облёт» (автовращение
для проектора), «⛶ Во весь экран» (Esc — выход), «🎥 Следовать» за выбранным самосвалом.

Клик по самосвалу или экскаватору открывает карточку: состояние, груз, топливо, моточасы, рейсы,
для самосвала ещё и оставшийся маршрут. Seed и число самосвалов (10–30) задаются в верхней панели.
В режиме «Сравнение» обе модели получают одно и то же модельное время и одинаковые события;
ручная поломка тоже применяется к обеим.

**Сценарий для жюри (2 минуты):** раздел «Эффект», x20. Через минуту нажать
«Вызвать поломку»: Э-1 на сульфиде ломается. Слева самосвалы стоят в очереди к сломанному
экскаватору, бункер дробилки пустеет, фабрика мигает «ПРОСТОЙ ОФ». Справа самосвалы
перераспределяются. Потом нажать «⏩ МАКС», досчитать смену и показать итоговое окно и блок
«Экономический эффект» (формула появляется при наведении).

| **Медь в концентрате, т/смену** | 109,9 | 110,7 | **+0,7%** |
| **Аварийные отказы самосвалов, шт/смену** | 4,4 | 1,1 | **−75%** |
| Отказов предотвращено плановым ремонтом | — | 3,3 | |
| Ложные тревоги прогноза, шт/смену | — | 0,7 | точность ≈ 82% |
| **Экономический эффект** | | | **≈ 5,9 млрд ₸/год** на сегмент из 20 самосвалов |

Умная стратегия добыла не меньше фиксированной во всех 20 сменах. Эффект складывается из
защиты фабрики от простоя, замены аварийных ремонтов плановыми, ровного качества руды (выше
извлечение меди) и меньших простоев. Между дробилкой и фабрикой стоит склад дроблёной руды
(буфер ~1,5 ч), поэтому короткие перебои подвоза фабрику не останавливают даже без системы —
эффект от защиты фабрики честно меньше, чем в модели без склада. Геометрия — как на реальном
Актогае: три выработки, три отвала вскрыши, дробилка и выщелачивание — по спутниковому снимку. Три
отвала помогают и расчёту без системы (вскрыша — на ближайший отвал), поэтому эффект теперь в основном
в плановых ремонтах вместо аварийных и в большем объёме перевозок. Ставки — оценки из `config.ts`, сверить с открытыми источниками.

Эффект зависит от того, чего в системе не хватает:

| Самосвалов | Δ добычи | Δ простоя фабрики | Δ очереди | Эффект, ₸/год |
|---:|---:|---:|---:|---:|
| 15 (самосвалов мало) | +7,9% | −89% | −58% | ≈ 19,2 млрд |
| 20 (по умолчанию) | +4,7% | 1,4 → 0 мин | −16% | ≈ 5,9 млрд |
| 25 (самосвалов с запасом) | −0,1% | простоя нет в обоих | −1% | ≈ 6,3 млрд |

Если самосвалов с запасом, узким местом становятся экскаваторы: склад полон, фабрика почти не
стоит и без системы, а диспетчеризация почти не добавляет тоннажа (не меньше фиксированной лишь в 9 сменах
из 20). Эффект тогда — в качестве руды и плановых ремонтах вместо аварийных. Это честный результат, и о нём стоит
сказать на питче.

## Архитектура

```

    config.ts          ВСЕ параметры (с комментариями «оценка, сверить…»)

    rng.ts             детерминированный ГПСЧ mulberry32 + хэш-шум
    graph.ts           граф дорог, Dijkstra, маршрутизатор с кэшем и закрытиями
    mine.ts            генерация геометрии карьера: уступы, 2 спиральных съезда, бермы, забои
    engine.ts          тиковая симуляция (шаг 1 с), события, учёт времени и топлива
    dispatch.ts        стратегии: FixedStrategy и SmartStrategy
    ore.ts             содержание меди в забоях, извлечение на фабрике
    health.ts          датчики самосвалов, тепловая модель, детектор деградации и прогноз отказов
    kpi.ts             KPI и экономический эффект
    __tests__/         Vitest
  render/drawMine.ts   Canvas 2D: статичный слой (кэш) + динамика каждый кадр
  render3d/            3D на Three.js
    terrain.ts         рельеф чаши с уступами по тем же контурам, что граф дорог; ленты дорог
    models.ts          низкополигональные самосвал, экскаватор, дробилка с силосом, ОФ, отвал, АЗС
    MineScene.ts       сцена: свет и тени, анимация, голо-панели (CSS2D), камера, выбор объектов
  components/          MineCanvas, KpiPanel, Charts (Recharts), InfoCard
  App.tsx              главный цикл requestAnimationFrame, режимы, управление
scripts/bench.ts       прогон стратегий по нескольким seed → BENCHMARK.md
```

**Модель карьера.** Три выработки, как на спутниковом снимке Актогая (31.03.2025): главный карьер
~1,7 × 1,1 км глубиной ~230 м, северо-западный ~0,8 × 0,4 км (~180 м) и юго-западный ~1,0 × 0,6 км
(~120 м; глубины малых — оценка). Контуры, центры и повороты измерены на снимке (`config.ts → pits`).
У каждой выработки уступы по 15 м, два спиральных съезда и кольцевые бермы; бровки соединены
дорогами (глубина и уступы — для 3D; время рейсов считается по длине дорог в графе и скоростям
гружёного/порожнего, уклон отдельно не моделируется). Пять экскаваторов: в главном карьере два на
сульфидной руде и один на вскрыше, в северо-западном — на оксидной руде, в юго-западном — на вскрыше.
На поверхности стоят первичная дробилка с приёмным бункером, конвейер на склад дроблёной руды
(конусный штабель), конвейер из тоннеля под складом на обогатительную фабрику,
площадка кучного выщелачивания (оксид), отвал вскрыши (запад) и гараж/АЗС.

**Движок.** Шаг фиксированный (1 с). Самосвал проходит цикл: `idle → порожний рейс → очередь →
погрузка → гружёный рейс → очередь → разгрузка → …`, плюс заправка и поломка. Скорость
гружёного 20 км/ч, порожнего 35 км/ч, у каждой машины свой коэффициент ±10% (из-за этого машины
сбиваются в пачки). Расход топлива разный в рейсе гружёным, порожним и на холостом ходу.
Самосвалы разгружаются в приёмный бункер дробилки (1000 т). Дробилка перегружает руду на склад
(80 т/мин, ёмкость 4500 т, на начало смены 2700 т), фабрика непрерывно забирает со склада 50 т/мин.
Если склад пуст — простой фабрики; если склад полон — дробилка ждёт. Двойник `stockpile`: уровень,
заполнение, запас в часах, % Cu штабеля, отсыпка и выдача (конвейерные весы), пыль.

**Честное сравнение.** Все случайные события генерируются заранее из seed, отдельными потоками
ГПСЧ: поломки экскаваторов, закрытия участков съездов, поломки каждого самосвала (поток привязан
к номеру машины). Поэтому обе стратегии получают одинаковый сценарий. Шум времени погрузки — это
хэш от (seed, самосвал, рейс, экскаватор). Тест проверяет, что одинаковый seed даёт
бит-в-бит одинаковые KPI.

## Алгоритм диспетчеризации

**Фиксированная (базовая).** Плановик в начале смены распределяет самосвалы по экскаваторам
пропорционально `план по материалу × расчётное время цикла` (метод наибольших остатков) и
закрепляет их на всю смену. Это сильная, а не «соломенная» база: распределение оптимально для
спокойной смены. На поломки и очереди она не реагирует. При поломке экскаватора его самосвалы
ждут ремонта.

**Умная (наше решение).** Решение принимается каждый раз, когда самосвал освобождается после
разгрузки или заправки. Кроме того, порожние самосвалы в пути пересматривают цель при любом
событии: поломке, ремонте, закрытии или открытии дороги. Для каждого экскаватора `e` считается

```
оценка(e) = ETA проезда (Dijkstra с учётом закрытых участков)
          + ожидание = прогноз очереди: самосвал под погрузкой, очередь, уже едущие порожние
                       и гружёные, которые вернутся на свою петлю после разгрузки
          + время погрузки (зависит от производительности экскаватора)
          + задержка, которую наш приезд создаст тем, кто приедет позже
          − бонус отставания экскаватора от целевой доли плана (с мёртвой зоной ±2 рейса)
          − бонус отставания материала от плана смены
          − бонус угрозы простоя дробилки (прогноз бункера и склада на 35 мин вперёд) — только сульфид
```

У самосвала есть своя «петля», и по умолчанию он остаётся на ней. Он перезакрепляется, только
если выигрыш больше порога (`stickinessSec`). Так диспетчер не гоняет машины через весь карьер
ради мелких выгод: первые версии без этого проигрывали фиксированной схеме из-за лишних
порожних пробегов. При поломке экскаватора его очередь сразу перераспределяется, а самосвал
под погрузкой уезжает недогруженным, если набрано не меньше 30%.

## Прогноз отказов (предиктивная диагностика)

У каждого самосвала есть датчики: **температура двигателя, вибрация рамы, давление в шинах**
(опрос раз в 10 с). Неисправности генерируются заранее из seed. У ~75% отказов есть период
деградации 60–120 мин, когда «дрейфует» один параметр:
- двигатель — растёт температура;
- гидравлика/подвеска — растёт вибрация;
- шины — падает давление.

Остальные ~25% отказов внезапные, их предсказать нельзя. Ещё у части машин бывают безобидные
аномалии (жара, грязный радиатор), которые дают ложные тревоги, как в реальной жизни.

**Детектор (модельный подход двойника).** Двойник знает, какой *должна* быть температура
в текущем режиме (тепловая модель: гружёный > порожний > холостой ход, постоянная времени
~10 мин), и смотрит на невязку «измерено − ожидается». Невязки трёх датчиков нормируются,
сглаживаются, по истории за 15 мин считается тренд и **время до отказа**. Когда индекс
деградации растёт и превышает порог, поднимается тревога, а умная стратегия отправляет
самосвал на **ППР** (сразу, если он порожний, иначе после разгрузки). Плановый ремонт идёт
в 3 раза короче аварийного и дешевле (нет эвакуации с трассы и вторичных повреждений).

На 30 сменах (≈90 предсказуемых отказов) тревога срабатывает в среднем за **46 мин** до отказа
(от 13 до 91 мин), пропусков предсказуемых отказов нет, точность тревог около 82%.

В интерфейсе: панель «⚡ Прогноз отказов» (топ по риску, клик открывает карточку), в карточке
самосвала датчики и график «датчик против модели» за последний час, на картах значок `⚡ риск %`.

## Взрывные работы

По графику смены — один плановый взрыв в обед, на 6-м часу смены (± 10 мин, забой — из seed), — блок у забоя взрывают: за 15 мин
объявляется предупреждение, затем 30 мин оцепления. Экскаваторы в зоне радиусом 240 м стоят,
дороги внутри зоны закрыты (если это не отрезает другие объекты), самосвал под погрузкой
выводится из зоны. График известен заранее, поэтому **умный диспетчер не отправляет самосвалы
к забою, погрузка у которого попадёт в оцепление**, и уводит их ещё во время предупреждения.
Фиксированные самосвалы приезжают и ждут у оцепления. Кнопка «💥 Взрыв» (клавиша E) объявляет
внеплановый взрыв у выбранного экскаватора. В 3D видны жёлтый «купол» предупреждения, вспышка,
облако пыли и красная зона оцепления.

## Качество руды (шихтовка)

У каждого рудного забоя своё содержание меди: глубокий Э-1 богаче (~0,42% Cu), верхний Э-2
беднее (~0,29%), и по ходу отработки оно плавно меняется (неоднородность рудного тела).
Бункер дробилки и склад смешивают руду. Фабрика лучше всего работает при ровном питании около
**0,35% ± 0,03% Cu**: каждое отклонение снижает извлечение меди в концентрат (оценка:
отклонение 0,05 п.п. → извлечение ниже на 4 п.п.).

Умный диспетчер смотрит на прогноз содержания в бункере с учётом уже едущих самосвалов. Если
руда беднее цели, он даёт бонус богатому забою, если богаче — бедному. Фиксированное
закрепление держит пропорцию, но не реагирует на дрейф качества в забоях. На экране: подписи
`% Cu` у экскаваторов и бункера, график «Медь в руде на фабрику» с целевым коридором,
показатели «Качество руды на ОФ в норме» и «Извлечение меди».

## Экономический эффект

За прошедшую часть смены считаются три разницы, их сумма экстраполируется на 12 ч, затем на год
(670 смен):

```
Эффект/год = [ (простои фикс − простои умн)·ставки
             + (простой фабрики фикс − умн)·15 млн ₸/ч
             + (л/т фикс − л/т умн)·тонны·цена дизеля
             + (аварийные ремонты фикс − (аварийные + плановые) умн)·стоимость
             + (доля потерь меди фикс − умн)·медь в питании·цена меди ] × 670
```

Дополнительная добыча показывается отдельно и в деньги не переводится (консервативная оценка).
В интерфейсе формула с подставленными числами видна при наведении на блок эффекта.
Блок появляется после первого часа смены, раньше экстраполяция слишком шумная.

## Как менять параметры

Все параметры лежат в `src/sim/config.ts`, у каждого есть комментарий. Все значения — **оценка,
их нужно сверить с открытыми источниками (годовые отчёты KAZ Minerals)**:

- `planT` — план смены по сульфиду, оксиду и вскрыше, т;
- `dumps.crusher.plantFeedTpm` — потребление фабрики, т/мин; `binCapT` — бункер;
- `truck.*` — грузоподъёмность, скорости, расход, бак, вероятность поломки;
- `excavators` — состав, материал, производительность, горизонт и угол забоя;
- `economics.*` — цена дизеля (₸/л), стоимость часа простоя самосвала, экскаватора и дробилки,
  стоимость аварийного и планового ремонта, число смен в году;
- `blasting.*` — число взрывов за смену, длительность оцепления, радиус зоны, предупреждение;
- `grade.*` — целевое содержание Cu и коридор, изменчивость забоев, извлечение; `excavators[].gradePct`;
- `health.*` — доля предсказуемых отказов, длительность деградации, порог тревоги, ложные аномалии;
- `smart.*` — веса умного диспетчера.

После изменений запустите `npm test` и `npm run bench`.

## Запуск на платформе OpenEgiz

Вместе с платформой приложение запускается из корня репозитория командой `make aktogay`
(см. корневой README.md). Сервис `service/main.ts` создаёт двойники в Ditto и публикует
телеметрию, а интерфейс читает состояние из Ditto. `Dockerfile.sim` и `Dockerfile.ui` собирают
эти два контейнера.

## 3D-сцена

Карьер окружён степью, уходящей в дымку на тёмном фоне. Три выработки (главная ~230 м): уступы по 15 м, дороги-полки врезаны в борта (бермы и откосы), зелёный оттенок в зоне окисления, подтопленное дно, россыпь камней, мачты освещения по бровке, мягкое свечение (bloom) фонарей, окон и колец статуса. Дороги повторяют рельеф. Самосвалы (красный кузов, светлая кабина) и экскаваторы (стально-синий корпус, светлая стрела) — модели, увеличенные ×2,2,
чтобы их было видно на карьере шириной 3 км. Каждый кадр сцена читает состояние той же модели,
что и 2D-схема:
- кольцо под самосвалом и проблесковый маячок окрашены в цвет состояния; кузов виден с грузом
  цвета материала и опрокидывается при разгрузке;
- платформа экскаватора поворачивается между забоем и самосвалом, стрела «копает»; индикатор
  состояния: зелёный — работа, жёлтый — ждёт самосвал, мигающий красный — поломка;
- уровень в силосе дробилки, по конвейеру на ОФ идёт руда; при простое конвейер мигает красным;
- закрытый участок съезда подсвечен красным, на нём шлагбаум;
- стоянка у гаража — часть дорожного графа: у каждого самосвала своё место, он заезжает на него
  вперёд по проездам и выезжает задним ходом; место бронируется при отправке на заправку или ППР;
- голографические панели над дробилкой, ОФ, отвалом и выщелачиванием показывают живые цифры
  (как 3D-сцены в Grafana/OpenTwins).

Для переноса на OpenEgiz ту же сцену можно собрать в Unity (плагин `grafana-panel-unity`).
Геометрию карьера и логику состояний можно брать из `src/render3d` и `src/sim`.

## Принятые решения

- Скорость x1 = 10 с смены за 1 с реального времени: x20 прогоняет смену примерно за 3,5 мин
  (удобно для живого демо), «⏩ МАКС» — примерно за секунду.
- Моделируется сегмент парка (10–30 самосвалов, 5 экскаваторов). План и производительность
  фабрики масштабированы под этот сегмент.
- В начале смены бункер дробилки полон, на складе 2700 т (около часа работы фабрики), поэтому
  первые гружёные самосвалы приезжают раньше, чем фабрика успевает остановиться.
- Самосвалы держат дистанцию 70 м до впереди идущего на той же полосе и ждут, если он встал
  (сломанный самосвал съезжает на обочину и движение не перекрывает). Обгонов нет.
- Ручная поломка в режиме сравнения применяется к обеим моделям одновременно.
- Цвета графиков проверены на различимость при дальтонизме и контраст на тёмном фоне.
  Цвета статусов (зелёный/красный) не используются для серий.
